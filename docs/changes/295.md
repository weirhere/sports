## Decision

**On Box score, the game page's tab swipe hands off at a table's edge.** A drag that scrolled one of the box score's sideways tables belongs to the table and never changes tabs. A swipe goes to Roster (or back to Plays) only if no table moved during it, which in practice means a fresh swipe once the table is already at its end. On this tab it also has to travel 100pt instead of the usual 50. Each table reports its scroll offset clamped to the scrollable range (`onScrollGeometryChange`), so rubber-banding past the end doesn't count as moving. `TabSwipeLedger` holds that verdict for the drag in progress without going through view state. Every other tab's swipe is unchanged.

## Why

Raim, 2026-11-02: scrolling a box score right "almost always takes me to the next tab, roster, unless i scroll really slowly." The tab swipe is a `simultaneousGesture`, so it fired alongside the table's own horizontal `ScrollView`. Any mostly horizontal drag over 50pt flipped the tab when the finger lifted, whether or not the table had scrolled. Andy turned down the first fix, which turned the swipe off for the whole tab the way the bracket and NFL standings do: he still wants to reach Roster by swiping from Box score, just as a more deliberate choice because the tab scrolls sideways itself. Handing off at the edge is how nested scrollers behave across iOS: the inner one takes the gesture until it has nothing left to scroll, and the next gesture goes to the outer one. The longer threshold covers drags that start off the tables (the team picker, card headers), where there's no edge to hand off from.
