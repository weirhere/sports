## Decision

**`header.gameNote` and `status.isTBDFlex` are wired onto the domain model; `status.type.altDetail` stays DTO-only.** BACKLOG.md's "small unread fields" row (E21) read as fully decoded as of 2026-10-04, but walking the backlog for the next closeable item found two of its six fields were DTO-only: the `Decodable` struct carried `SummaryHeaderDTO.gameNote` and `StatusDTO.isTBDFlex`, with tests proving the DTO itself parses them, but neither was ever mapped onto `GameSummary` or `Game` — so neither was reachable from any view, contrary to what the row implied. `GameSummary` gains `gameNote` (mapped in `ESPNMapper.gameSummary(from:)`); `Game` gains `isTBDFlex`, mapped on **both** paths that build a `Game` — the scoreboard's `game(from: EventDTO...)` and the team schedule's `game(from: ScheduleEventDTO...)`, since the schedule path constructs `Game` independently rather than reusing the scoreboard mapper. The three places that rebuild a `Game` by hand instead of copying it (`withLiveState`, `SpoilerGuard`'s `withRecords` and `concealed`) each gained the matching `copy.isTBDFlex = isTBDFlex` line, the same struct-copy trap this epic has caught before. `altDetail` is untouched on purpose: the row's own text already scoped drawing from it as a separate change, and a domain field for it means touching `GameStatus`'s enum cases, not adding a sibling field — out of scope for this pass.

## Why

This session has no Mac, no simulator and no ESPN egress, so the actionable backlog work is a decode/model fix verifiable by unit tests against fixtures already held in the repo — and BACKLOG.md's own claim that this row was done except for drawing turned out to be half wrong on inspection. Leaving the stale claim in place risks a future session reading "decoded" and moving on, the exact failure mode the backlog's reconciliation passes (BACKLOG.md's "Reconcile the backlog against the code" row) keep finding.
