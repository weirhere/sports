## Decision

**The decisions log and the web-parity ledger are frozen; each PR records its decisions in its own `docs/changes/<pr>.md`, and the readable tables are assembled at build time.** `docs/decisions.md` stops at 402 rows and `docs/web-parity.md` at 323. A change file carries `## Decision`, `## Why` and a required `## Web parity` status (`shipped` / `pending` / `n/a` / `differs`), with an optional `## Backlog`; several decisions per PR repeat the block. `scripts/build-changelog.py build` writes the frozen file plus every change-file row to the gitignored `docs/generated/`, which web CI builds and uploads on every run. `check-parity-ledger.sh` keeps its name and delegates to the validator, which also fails a branch that grows a frozen file. The `[skip-parity]` token is gone. Both frozen files are `merge=union` in `.gitattributes` so a branch cut before the cutover merges main cleanly and meets the CI message rather than a conflict.

## Why

Two append-only tables that every PR writes the last line of conflict with each other by construction. Measured on the day: of the 80 most recently merged PRs, 72 touched a ledger and 31 had another ledger PR merge while they were open, each a hand-resolved conflict on a row nobody disagreed about, and CLAUDE.md carried a standing instruction for resolving it. Two files from two PRs cannot conflict, so the shared file becomes a build output. The parity status moves inside the entry because the old check counted rows in two files to prove someone had written the second one; a required section proves the same thing with nothing to count and no escape hatch to misuse. Union merge on the frozen files is for the branches already open, not the future.

n/a — repository process, no product surface. The ledger itself is the web's record and is unchanged in content.
